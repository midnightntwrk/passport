# ECC validation reproductions

These tests support [the review](../ecc-validation.md#71-completed-executable-checks).
They exercise released Midnight ZK libraries and native Ledger crypto APIs, with
explicit controls and adversarial inputs. They do not compile a Compact contract
or submit a transaction.

From the repository root:

```sh
cargo test --locked --manifest-path research/ecc-validation-checks/Cargo.toml -- --nocapture
python3 research/ecc-validation-checks/run.py consumer -- --nocapture
python3 research/ecc-validation-checks/run.py ledger /path/to/pinned-ledger -- --nocapture
```

The direct Cargo suite pins circuits 7.2.4, curves 0.3.1, proofs 0.8.3 and stdlib
2.3.5. The consumer runner uses the identical source with proofs 0.8.2 and its
separate lockfile. Each has five tests: altered coordinates versus decoder and
constraints, generic identity, torsion and mixed torsion, full proof verification,
and trailing bytes in a processed verification key.

The Ledger runner requires a clean isolated checkout at
`67f9f97246339539af0091c4d8c6bc5ab236a191` (Ledger 9 rc.5). It validates that
checkout and creates a temporary Cargo project with path dependencies on its
`transient-crypto` and `serialize` packages. It runs the three tests in
[ledger-api.rs](ledger-api.rs) with Rust 1.95, the specified backend versions,
and the supplied harness lockfile. That lockfile captures the tested dependency
resolution; it is not the complete Ledger workspace lockfile. The runner leaves
the checkout unchanged. Cargo caches and the reusable target directory are the
only persistent build outputs.

Proof setup uses locally generated, test-only KZG parameters. For the altered
witness, both proof-generation rejection and verification rejection of generated
bytes count as rejection; the recorded runs generated bytes and failed verification.
The valid control must verify successfully. Torsion tests deliberately forge an
unchecked subgroup wrapper to test the constraints themselves, and catch expected
coordinate-construction panics. Panic messages under `--nocapture` are expected.
