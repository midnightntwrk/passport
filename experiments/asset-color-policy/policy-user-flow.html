A policy-gated send

Proposed ACC flow · Compact 0.35
01

User → Send

Choose asset, amount and recipient; authorize through Passport.
Policy gate on spending; no deposit check.
02

Transaction builder → Execute locally

Wallet / dApp runtime · no issuer server call
Code source → BuilderGenerated modules for ACC, registry and selected policy. Cached or loaded on demand.
Indexer → BuilderOn-chain state for all three, read at a shared block snapshot.
03

Prover → Produce linked call proofs

ACC + registry + selected policy←ZKIR + proving keys
Local prover or remote proving service; private proving inputs follow that choice.
04

Network → Verify and apply the transaction

Contract call proofs and state checks accompany the asset release.
Experiment boundary: ACC → policy and registry → policy dispatch tested separately. Combined ACC routing and end-to-end proving/submission remain untested.
