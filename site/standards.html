Standards & feature-complete v1.0

A standards-and-spec body that survives external review. Every MIP names an external co-author or committed reviewer from the start — a wallet partner or ecosystem reviewer — so what we ratify is a shared standard, portable across wallets. Cryptographer and formal-methods reviews are scheduled against component stability, not against a Passport-internal calendar.

For implementers: start here

  1. Read MIP-0012 — how a contract holds and releases unshielded and shielded value, with authorisation abstracted to one seam.
  2. Then MIP-0013 — the device set, revocation epochs, the bootstrap, and the seam instantiated with in-circuit Schnorr over JubJub.
  3. Clone the reference implementation — both standards in one deployment, with the conformance suites the standards require and an independent bit-exact Rust signer.
  4. Build your signer first — it needs only JubJub arithmetic and SHA-256, no Midnight stack, so approval is separable from proving from day one.

A second, independent implementation is the standards’ remaining path-to-Active evidence — if you build one, say so in the upstream discussions.

Pipeline

The MIP pipeline

Sequenced by dependency. Every MIP names an external co-author or committed reviewer from the start — that is what makes it portable across wallets rather than a Passport-shaped specification. STD-03 is a cryptographic prerequisite that ships before any MIP that hashes user state. Each card carries its upstream lifecycle state and links its evidence.

A note on identifiers: four-digit ids (MIP-0003, MIP-0007, MIP-0008, MIP-0012, MIP-0013) are upstream-assigned numbers. Short ids (MIP-4…) are workspace pipeline labels for proposals not yet filed, which carry the literal mip-xxxx filename until an upstream editor assigns a number at merge.
